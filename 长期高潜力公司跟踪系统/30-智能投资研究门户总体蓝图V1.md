# 智能投资研究门户总体蓝图 V1

版本日期：2026-04-14

系统正式名称：

- 中文名：`竹鉴`
- 英文名：`Bamboo Lens`

## 一、我们已经达成的共识目标

这套系统的目标，不是做一个只会推送新闻的提醒器，也不是做一个静态资料库。

它要成为一套持续运行、持续沉淀、持续进化的投资研究系统。

后续在产品语境里，这套系统统一称为：

- `竹鉴 / Bamboo Lens`

你的使用方式已经很清楚：

1. 工作日

- 主要看每日推送的简报
- 快速知道最新发生了什么
- 保持对目标公司的持续感知

2. 周末

- 进入研究门户做系统学习
- 理解公司、行业、事件和框架
- 评估自己的投资决策

3. 长期目标

- 系统每天都能从新信息中沉淀知识
- 不断完善公司认知、行业认知和投资框架
- 逐步变成一个更懂投资、也更懂你的研究操作系统

---

## 二、这套系统最终要长成什么样

最终形态应该是一个 `云端运行 + 在线门户 + 结构化知识库 + 手机推送` 的系统。

它至少要同时具备四种能力：

### 1. 持续采集

- 每日自动收集公司、行业、政策、财报、电话会和重要变化

### 2. 结构化分析

- 每条事件都被拆成：
  - 事实
  - 判断
  - 动作
  - 优先级
  - 下一次验证点

### 3. 知识沉淀

- 新事件不是看完就丢，而是要持续沉淀到：
  - 公司主页
  - 事件流
  - 当前结论
  - 跟踪重点
  - 研究框架

### 4. 框架进化

- 系统要定期反过来总结：
  - 哪类信息最有价值
  - 哪类信号经常误导
  - 哪些筛选规则需要重写
  - 哪些分析框架应该升级

这才叫“会学习成长”。

## 三、现有本地资产怎么处理

现有本地内容不是负担，而是非常重要的起点。

### 现有资产一：研究资料库

目录：

- `长期高潜力公司跟踪系统/`

这里已经沉淀了：

- 筛选规则
- 分析框架
- 单公司模板
- 跟踪清单
- 数据库设计
- 协作协议
- 八家核心公司完整档案
- 多家公司动态更新样例
- 决策规则

它的价值在于：

- 是研究方法库
- 是知识种子库
- 是后续在线系统的底层内容来源

### 现有资产二：研究门户原型

目录：

- `研究门户/`

这里已经验证了：

- 首页时间线
- 公司主页
- 事件详情页
- 基础阅读结构

它的价值在于：

- 已经验证了用户体验方向
- 后续可以升级为在线门户前端

### 结论

现有本地系统不废弃，而是分工转型：

1. `本地资料库`
- 继续作为内容源和维护区

2. `本地门户`
- 继续作为原型和开发环境

3. `云端系统`
- 成为正式执行层和线上展示层

## 四、整体架构建议

建议拆成五层。

### 第一层：来源层

职责：

- 定义每家公司看哪些官方来源

包括：

- 财报页
- IR 页面
- 新闻稿
- 电话会材料
- 产品发布页
- 政策和行业关键来源

这一层决定系统“看什么”。

### 第二层：采集层

职责：

- 定时抓取最新内容
- 保留原始来源链接
- 提取发布时间和核心摘要

这一层决定系统“拿到什么”。

### 第三层：分析层

职责：

- 对抓到的内容做去噪
- 判断哪些信息真正重要
- 输出结构化事件

统一格式建议固定为：

- 公司
- 日期
- 事件类型
- 事实
- 判断
- 动作
- 优先级
- 对业务的影响
- 对估值 / 动作的影响
- 下一次验证点
- 原始来源链接

这一层决定系统“怎么理解”。

### 第四层：知识沉淀层

职责：

- 把新事件持续沉淀为长期知识

主要沉淀到四个对象：

1. `事件库`
- 保存每一条结构化事件

2. `公司状态`
- 保存公司当前结论、研究动作、风险和跟踪重点

3. `框架库`
- 保存筛选规则、分析框架、复盘结论

4. `复盘库`
- 保存过去判断、后来结果和修正记录

这一层决定系统“会不会越用越聪明”。

### 第五层：展示与推送层

职责：

- 让你在不同场景下以不同方式使用系统

展示分两种：

1. `移动端推送`
- 每日日报
- 每周周报
- 只发摘要，不发长文

2. `在线门户`
- 首页时间线
- 公司主页
- 事件详情页
- 研究规则页
- 历史复盘页

这一层决定系统“你怎么用”。

## 五、哪些内容适合用 Markdown，哪些适合用结构化数据

这是后面最关键的边界。

### 适合继续保留为 Markdown 的内容

这些内容更新频率低，但解释性强：

- 筛选规则
- 公司分析框架
- 决策规则
- 完整版公司档案
- 一页式研究卡
- SOP 和方法文档

### 适合转成结构化数据的内容

这些内容变化频繁，必须由系统动态维护：

- 最近更新事件流
- 公司主页的当前结论
- 当前研究动作
- 当前资金动作建议
- 当前跟踪重点
- 事件详情页内容
- 首页最近更新

### 结论

未来不应该是“所有东西都写成 md”，而应该是：

- `Markdown` 负责长期方法和深度沉淀
- `JSON / 数据表` 负责高频动态和当前状态

## 六、智能成长应该怎么实现

这里要特别强调：

系统可以成长，但不能是黑盒式“自己变聪明”。

应该采用 `可审计、可回溯、可修正` 的成长方式。

### 合理的成长方式

1. 每次新增事件，先归档到事件库
2. 再判断是否需要更新公司主页当前结论
3. 每周总结哪些事件真的有信息含量
4. 每月复盘哪些判断对、哪些判断错
5. 每季度提出框架修订建议

### 不合理的成长方式

1. 只堆资料，不形成判断
2. 自动改框架，但没有留下修改理由
3. 让系统直接替你做仓位决策

### 所以后续要增加一类输出

除了日报、周报、公司页和事件页，还要增加：

- `框架修订建议`
- `研究错误复盘`
- `信号质量回顾`

这三类内容会让系统真正“学习”。

## 七、实施路线图

### 阶段 1：稳定推送跑通

目标：

- 不依赖本地电脑
- 每日 / 每周稳定推送

范围：

- 云端定时执行
- 手机推送打通
- 先只做日报和周报

建议方案：

- `GitHub Actions + PushDeer / 企业微信`

### 阶段 2：在线门户跑通

目标：

- 门户不再依赖本地电脑在线
- 周末可直接在线阅读
- 首页只保留决策驾驶舱内容，不再堆砌过程类、教程类、纲领类说明

范围：

- 把本地门户升级为在线静态站点或云端门户
- 首页、公司页、事件页读取云端结构化数据
- 建一个统一的“规则与系统说明”入口，收纳筛选规则、估值规则、日报规则、系统蓝图和操作说明
- 首页只回答三件事：最近有什么变化、现在该看什么、是否触发投资动作

### 阶段 3：沉淀与回写机制跑通

目标：

- 每天新事件自动进入事件流
- 公司主页自动更新当前状态

范围：

- 建事件库
- 建公司状态数据
- 建门户数据生成流程

### 阶段 4：框架进化机制跑通

目标：

- 系统不仅更新公司，还能更新“看公司的方法”

范围：

- 每月研究复盘
- 每季度框架修订建议
- 研究错误数据库

### 阶段 5：补强财务与估值能力

目标：

- 公司主页具备真正有数据支撑的财务分析与估值判断
- 能回答“现在股价是高估、合理还是低估”，并说明这个结论依赖哪些假设

范围：

- 近 3-5 年财务数据表
- 关键指标趋势
- 估值口径
- 当前估值判断

### 阶段 6：建立估值模型层

目标：

- 把公司研究从“这家公司好不好”推进到“这个价格值不值得买”
- 用区间、假设和触发条件支持投资动作，而不是给一个假精确价格

范围：

- 当前股价、市值、现金、债务和企业价值
- 不同公司适配不同估值方法：
  - 平台公司：分部估值、净现金、回购、折价项
  - 制造公司：利润增速、PE 区间、现金流质量折扣
  - 半导体制造：周期中枢、资本开支回报、先进制程溢价
  - 云 / AI 平台：收入增长、毛利率、capex 回报、FCF yield
  - 电力 / 能源：EPS 指引、长期合同、FCF、EV/EBITDA
- 三档估值情景：保守、中性、乐观
- 市场当前隐含假设：当前股价大概在假设什么
- 估值结论：明显低估、合理偏低、合理、偏高、明显高估
- 投资动作：可分批、观察、等待、减弱优先级

原则：

- 不做“精确算命式估值”
- 每个估值结论必须能追溯到收入、利润、现金流、资产、合同或用户指标
- 估值模型必须和公司主页的财务地图、业务地图、最新动态联动
- 当新财报或重大事件出现时，估值模型要能解释结论是否变化

## 八、从今天起具体怎么推进

为了避免继续发散，建议后续严格按这个顺序推进。

### 第一步：确定云端正式执行方案

先定：

- 采用 `GitHub Actions`
- 手机推送优先选 `PushDeer`

这一步解决“稳定跑”。

### 第二步：搭第一版云端研究简报系统目录

建议新建：

- `云端研究简报系统/`

初始结构：

- `sources/`
- `collectors/`
- `analyzers/`
- `publishers/`
- `outputs/`

### 第三步：先只跑通日报

原因：

- 日报频率高
- 更容易验证系统稳定性
- 周报可以复用日报事件库

### 第四步：让首页时间线改读云端输出

这一步开始真正把“推送系统”和“门户系统”连接起来。

### 第五步：再做公司主页回写

重点是：

- 当前结论
- 最新动态
- 跟踪重点

### 第六步：补财务地图

因为这块要么做真，要么暂时不上。

### 第七步：补估值模型层

先做两个样板：

- 阿里巴巴：分部估值 + 净现金 + 港股 / 中概折价 + 云与 AI 期权
- 立讯精密：利润增速 + PE 区间 + 现金流质量折扣

再推广到：

- TSMC、Microsoft、NVIDIA、GE Vernova、Constellation Energy、汇川技术
