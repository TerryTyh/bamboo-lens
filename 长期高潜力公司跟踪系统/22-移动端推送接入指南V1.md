# 移动端推送接入指南 V1

版本日期：2026-04-11

目标：

- 让你在手机上稳定收到每日和每周简报提醒
- 不把微信变成长文阅读器
- 让“提醒层”和“正式阅读层”分开

## 一、推荐结构

最推荐的结构不是“把完整简报直接塞进微信”，而是：

1. `提醒层`
   发到微信、手机通知或企业微信
2. `阅读层`
   在 Codex Inbox 或研究门户里看完整内容

原因：

- 微信适合提醒，不适合读长文档
- 简报正文放在正式阅读层，阅读体验更稳定
- 这样后续更容易维护

## 二、三种可行方案

### 方案 A：Codex Inbox + 手机查看

适合：

- 先验证内容和节奏
- 不想折腾额外接入

特点：

- 当前已经可用
- 能直接追问和展开分析
- 但不是微信推送

### 方案 B：微信提醒 + 研究门户阅读

适合：

- 平时微信使用频繁
- 想在微信里收到一句话提醒和决策提示

建议推送内容：

- 今日一句话
- 1-2 条关键变化
- 研究动作
- 资金动作建议
- 一个“去门户或 Inbox 查看详情”的提示

不要推送完整长文。

### 方案 C：企业微信 / iPhone 推送工具 + 研究门户

适合：

- 你愿意接受比微信个人号更稳定的推送方式
- 希望提醒更像系统通知

## 三、如果你想走微信，建议优先顺序

从实际可行性看，我建议优先顺序是：

1. `企业微信应用消息或机器人`
2. `微信服务通知类桥接工具`
3. `只用个人微信手动转发`

原因：

- 个人微信直推通常不稳定，也不适合长期自动化
- 企业微信和服务通知类桥接更适合机器发送

## 四、你真正需要的推送内容结构

以后推送到手机端的内容，建议统一为：

### 每日日简报提醒

- 标题：
  核心跟踪池日简报 | 2026-04-11
- 内容：
  今天没有公司长期逻辑被推翻，但阿里巴巴和立讯精密各出现一条值得跟踪的质量信号。
  研究动作：阿里提升优先级，立讯需要二次验证。
  资金动作建议：阿里进入分批加仓候选，立讯暂停激进加仓。
  查看详情：研究门户 / Codex Inbox

### 每周周报提醒

- 标题：
  核心跟踪池周报 | 第 X 周
- 内容：
  本周核心跟踪池长期逻辑整体稳定，但制造链公司要提高对现金流质量的关注。
  本周最值得提高研究优先级：阿里巴巴
  本周最该暂停动作：立讯精密
  下周重点：阿里云、立讯现金流、TSMC 月度营收
  查看详情：研究门户 / Codex Inbox

## 五、接入时的工程建议

如果后续你让我继续落地接入，我建议这样做：

1. 自动化继续在 Codex 里生成完整简报
2. 再加一个“提醒脚本”
3. 提醒脚本把摘要发送到目标通道

这样系统结构会比较干净：

- Codex 负责生成内容
- 推送脚本负责发送通知
- 研究门户负责长期阅读

## 六、我建议你现在先做的选择

如果你现在要先选一个方向，我建议：

- `短期`：继续用 Codex Inbox 看完整简报
- `中期`：接一层微信/手机提醒，只发摘要
- `长期`：逐步把研究门户作为主阅读入口

## 七、下一步我可以继续做什么

如果你要我继续落地，我下一步最适合做的是二选一：

1. 继续在项目里做一个“摘要推送脚本骨架”，方便后续接微信或企业微信
2. 继续完善研究门户，把它做得更像真正的在线研究中心
