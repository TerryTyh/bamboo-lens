# 核心跟踪池动态更新面板 V1

版本日期：2026-04-11

这份面板的目标，是把“静态档案”变成“可持续更新的研究系统”。

使用原则：

- 只记录会改变长期逻辑、盈利预期、估值框架或管理层判断的事件。
- 每条更新都要区分 `事实`、`判断`、`动作`。
- 不用每天把所有新闻都写进去，只更新值得入库的变化。

## 一、统一更新格式

每次新增动态，固定写成：

| 日期 | 公司 | 事件类型 | 事实 | 判断 | 动作 | 优先级 |
| --- | --- | --- | --- | --- | --- | --- |
|  |  |  |  |  |  |  |

事件类型统一使用：

- `财报`
- `电话会`
- `产品/技术`
- `政策/监管`
- `行业数据`
- `竞争对手`
- `资本配置`
- `股价/估值`
- `管理层`

优先级统一使用：

- `P1`：直接影响长期逻辑
- `P2`：影响 1-4 个季度经营判断
- `P3`：噪音或仅作记录

## 三、动态更新后的结论动作

每次重大更新后，只允许输出以下动作之一：

- `提升优先级`
- `维持原判断`
- `需要二次验证`
- `下调确信度`
- `降级出池`

## 四、避免跟踪失真

动态跟踪最容易犯的错误有四个：

1. 只记录新闻，不更新结论。
2. 只看股价，不看经营质量。
3. 只看公司自己说什么，不看行业和竞争对手。
4. 只看短期数据，不看长期逻辑是否变化。

所以每次更新后，必须补一句：

`这条信息改变了什么，没改变什么。`
