# 竹鉴晨报 | 2026-05-30

## 1. NVIDIA｜AI 工厂叙事升级：用 token 经济学定义基础设施效率，把智能体推理负载推到“持续产出”模型

**原文讲了什么**

原文把 AI 工厂定义为“制造智能的新型基础设施”：工业时代电厂把能量变成电力，AI 时代 AI 工厂把能量变成 tokens（推理模型/智能体系统的产出单位）。因此它的经济学指标不再是单纯算力峰值，而是 tokens per second、tokens per watt、每 token 成本、利用率与 uptime。

文章强调：在这种模型下，单位功耗性能会更直接映射到收入能力，而每 token 成本决定每个 AI 工厂（无论云端还是企业本地）能否跑出正向 ROI。AI 不再只是软件，而是持续产出的“必需基础设施”。

原文进一步把工作负载变化讲清楚：智能体系统会“推理-规划-检索-写代码-调用工具-执行动作”，并且会生成子智能体与合成数据，使得单次任务更长、更深、更计算密集；因此基础设施必须是全栈协同（模型、计算、网络、内存、存储、软件编排、CPU、供电与散热）来保持工作流持续前进。

**业务影响**

业务上，token 经济学的核心是把“推理与智能体工作流”变成可计量、可优化、可对标的产出过程：当客户关注每 token 成本与利用率，NVIDIA 的系统级组件（GPU+网络+软件编排+存储/内存子系统）就更容易以整套方案被采购和持续迭代，从而提高切换成本与生态黏性。对于 NVIDIA 来说，这意味着：网络与软件（以及机架级系统交付能力）将更直接参与收入结构，而不是只作为 GPU 的附属加速器。

**估值/动作影响**

估值层面，它把关键变量从“训练需求增长”扩展为“持续推理/智能体带来的 token 产出与利用率”。如果后续客户案例/财报能证明推理占比提升并带动系统利用率、网络/软件渗透与平台化成交，那么市场愿意给予更高的长期增长与利润中枢假设；反之，如果 token 叙事只能停留在营销层而无法转化为可验证的 ROI 与采购节奏，则不应据此上调估值中枢，只作为跟踪框架使用。

**后续观察点**

- 在后续财报/电话会中，是否出现可量化的推理/智能体负载指标（推理占比、token 相关 KPI、利用率、客户 ROI 口径）而不是仅叙事描述。
- 超大客户与企业客户的 资本开支 口径：是否从训练高峰转向“持续推理+智能体工作流”的稳定扩张，采购是否更多以机架/整系统而非单卡形态体现。
- 网络与软件的兑现：Spectrum-X/ConnectX 等网络业务与软件栈在订单/收入中的权重是否持续上升，并能解释为 token 经济学驱动的系统级升级。
- 能效与每 token 成本的外部佐证：是否出现第三方/客户披露，证明新一代平台在每 token 成本、tokens/W 或吞吐/延迟上形成可复用优势。

## 2. NVIDIA｜Vera CPU 首批基准披露：88 核 Olympus + 1.2TB/s 带宽，NVIDIA 把 AI 工厂 CPU 平台化再推进一步

**原文讲了什么**

原文用“智能体 AI 让 AI 工厂的 CPU 需求发生变化”作为切入：除了核心数，更关键的是在全核持续高负载下仍能维持高性能，同时提供极高内存带宽来支撑编排、数据处理、沙箱执行与工具调用等顺序型任务。

文章引用 Phoronix 公布的首批基准结果，称 Vera CPU 在单路平台下、450W TDP（内存功耗低于 30W）的功耗画像里，覆盖代码编译、压缩、转码、Python/Java、数据库等多类工作负载取得代际提升，并把它描述为对 Intel/AMD x86 CPU“最强竞争者之一”。

文中把 Vera 的关键设计点明确为：88 个定制 Olympus 核心（Armv9.2 兼容）、1.2TB/s 内存带宽、片上互连（Scalable Coherency Fabric）与 LPDDR5X 内存子系统，通过“每瓦内存性能”来服务智能体工作负载的高利用率与带宽持续性。

**业务影响**

对业务的直接影响路径是“AI 工厂平台化”：智能体工作负载把更多 CPU 侧任务（编排、运行时、数据处理、工具调用）推到高持续负载与高带宽需求上，Vera 的定位是把这些 CPU-heavy 任务与 GPU 推理/训练系统打包成一体化平台。若客户在同一供应商体系内同时采购 GPU、CPU、网络（如 ConnectX/Spectrum-X）与软件编排层，NVIDIA 的系统级议价权与方案粘性会更强；反之，若生态迁移阻力大（Arm 兼容/性能、内存形态、软件栈适配），Vera 可能更像“平台补全”而非新增大规模收入引擎。

**估值/动作影响**

短期不应因为一篇博客上调收入预测，但它把“AI 工厂”从 GPU 单品叙事推向全栈基础设施的可扩张 TAM：一旦 CPU 纳入同一套机架/平台成交，单客户 ARPU 与系统毛利结构可能更有弹性。估值层面更应把它当作“护城河强化”的证据：若未来财报/客户案例能证明 CPU 平台在智能体负载下带来更低每 token 成本、并带动整套系统中标率提升，则可以支持更高的长期渗透率假设；否则维持为技术储备，不提前兑现估值。

**后续观察点**

- Vera 的量产与供货时间表：是否明确进入 OEM/超大客户的实际采购与交付节奏（而不是仅基准展示）。
- 真实客户负载验证：是否出现可复现的第三方或客户侧数据，证明在智能体/推理编排负载下的性能/能效优势可迁移到生产环境。
- 生态与软件栈迁移：Arm 平台在主流数据中心软件（数据库、运行时、编排、可观测性）上的兼容性与性能回归成本是否可控。
- 是否带动平台打包：后续订单/渠道信息中，Vera 是否与 GPU/网络/软件以“AI 工厂整机/机架级”形式联合成交。
