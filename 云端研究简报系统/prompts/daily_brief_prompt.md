# 日报生成规则

目标：

- 围绕核心跟踪池生成一份工作日日报
- 只保留真正改变长期逻辑、盈利预期、估值框架或管理层判断的变化
- 只使用自动化 event_store 中已经完成研判的正式动态作为“今日关键变化”
- 不把官方候选、标题抓取、日历提醒、网页导航文字包装成研究判断

输出格式固定为：

1. 今日关键变化 / 今日可读内容
2. 最多 3 条关键变化
   - 公司
   - 事件
   - 核心内容
   - 关键证据
   - 为什么重要
   - 动作
3. 下一次验证点
4. 明日重点

不要输出“一句话结论”“今日跳过”“今日无需动作”这类低信息密度段落。用户要看的是内容本身：原文讲了什么、为什么和公司有关、对业务/估值/动作有什么含义。

所有来源链接必须使用 Markdown 可点击格式，例如 `[打开原文](https://example.com)`。

动作只允许使用：

- 提升优先级
- 维持原判断
- 需要二次验证
- 下调确信度
- 降级出池

资金动作建议只允许使用：

- 继续观察
- 进入分批加仓候选
- 暂停加仓
- 适度降仓
- 逐步退出

正式动态质量门槛：

- 必须有原文或官方来源
- 必须读到足够正文内容，不能只有标题
- 必须有关键数字、管理层口径、业务事实或财务科目作为证据
- 必须能说明对业务、估值或投资动作的影响
- 必须给出下一次验证点

候选处理规则：

- 候选只能说明“发现了什么线索”，不能写成正式判断
- 如果候选只有标题、发布日期、网页入口，不能进入“今日关键变化”
- 如果当天没有正式动态，只发短日报和明日重点，不展开“今日关键变化”

写作要求：

- 不制造噪音
- 不堆新闻
- 不用空泛口号
- 不直接搬运英文片段；必须转成中文摘要
- 必须区分事实与判断
- 必须给出下一次验证点
- 每条关键变化至少包含一个具体数字、科目、产品、客户、订单、利润率、现金流、capex 或管理层原话层面的证据
- 禁止只写“长期逻辑强化”“值得关注”“继续验证”“提升优先级”等空判断
